# Contributing

Use synthetic evidence only. Do not copy development captures, local paths, device names, subscriber data, screenshots, credentials, pairing records, or private history into commits. Do not upload raw diagnostic artifacts to issues or pull requests.

Keep measurements, user reports, inference, and uncertainty separate. Preserve exact device targeting and capture retention. Avoid protected entitlements and security bypasses. Destructive or carrier-account actions do not belong in the application’s automated tests.

Before proposing a change, run the Swift tests, Python tests, publication scan, and clean build in the README. Add synthetic regression cases for parser, comparison, or export changes. Test exported bytes/ZIP content rather than a duplicate redaction implementation. A new Share-Safe field needs a defined grammar or fixed choices and canary coverage. Keep raw capture useful in Private Diagnostic Export.

Write short, clear explanations. Use one term per concept. Describe observed evidence before a conclusion. Document compatibility failures as unavailable data, not success.

The candidate proposes MIT. The owner must approve and apply the project license before accepting public contributions. Contributors must have rights to their changes. No contributor agreement, support guarantee, or private reporting address is invented by this candidate.
